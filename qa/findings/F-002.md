# F-002: Coverage status: which source, and is it per case?

| Field | Value |
|---|---|
| Severity | major |
| Owner | 00-main (contract and link_patterns); affects 03-nav |
| Contract section | §7.0, WI-7, link_patterns.H_COVERAGE_STATUS / H_ADJ_BASE |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

* WI-7 says *"Coverage decisions read the explicit Valuation_Coverage_Status column, never ISNUMBER(FV) alone"*, but
  `H_COVERAGE_STATUS` decides MODEL_VALUED from `[@Base_Fair_Value]=""`. It never reads
  `tbl_ValuationOutputs[Valuation_Coverage_Status]`. A row that 02-valuation marks UNVALUED while still carrying a Base FV
  (for example an invalid model kept for display) would be MODEL_VALUED in the holdings.
* §7.0 says MODEL_VALUED needs "a valid tbl_ValuationOutputs row **for the case**", and `classify.coverage_status(line, case)`
  takes a case, but the workbook has a single `Valuation_Coverage_Status` column, computed from Base. If a Bear (or
  Selected) fair value is blank while Base is present, the Python reference makes the line UNVALUED for Bear (adjustment 0).
  The workbook keeps it MODEL_VALUED, and the Bear variant of `H_ADJ_BASE` evaluates `w × (""/P − 1)` = `#VALUE!`. The
  Selected case has the same issue when Fundamental mode selects a blank case.

## Reproduction / evidence

`tests/independent/test_I_compare_workers.py::test_I_CMP_11` compares per-case status; W-03c compares per-case Fair NAV.

## Proposed resolution

Make the status per case in both places (Adj_<case> uses the case FV's blankness), or define all cases to use the Base status and require Bear/Bull to be present whenever Base is. Make H_COVERAGE_STATUS also read tbl_ValuationOutputs[Valuation_Coverage_Status], as WI-7 requires.
