# F-001: Method 2/3: basis for MARKET_PASS_THROUGH positions and behaviour for unmarkable lines

| Field | Value |
|---|---|
| Severity | major |
| Owner | 00-main (contract); affects 03-nav |
| Contract section | §7.3, §7.4, §7.5a; workbook_interface link_patterns.H_MV_MKT |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

Two careful readers implement Method 2/3 differently:

1. **MARKET_PASS_THROUGH POSITION lines** (debt, money market, REIT/InvIT with a quantity and a price). §7.3 defines
   `ONA = Σ CARRYING_VALUE and MARKET_PASS_THROUGH line values` and `NA_mkt = Σ_equity MV_i^mkt + ONA`, i.e. these lines
   enter at their **disclosed** `Market_Value_INR_Cr`. `link_patterns.H_MV_MKT` computes `MV_Mkt_INR_Cr = q × P / 1e7`
   for **every** POSITION line, so a workbook that sums `MV_Mkt_INR_Cr` marks them at **q × P** on `in_Price_Date`.
   The two differ whenever the price moved since `Portfolio_Date`. Method 3 has the same split (are debt lines marked at the
   scenario price or held at the disclosed value?). PPFAS Flexi Cap holds debt and money-market lines, so this affects the
   G1 fund directly. The contract cases (T-NAV-*) contain no MARKET_PASS_THROUGH position, so no test pins it.
2. **Unmarkable lines.** §7.5a says Method 2/3 show `#N/A` while a POSITION is not MATCHED, but `NavResult.nav` is typed
   `float`; the Python reference behaviour (None, raise, or a number) is undefined, so W-03 cannot know what to compare.
3. A POSITION that is not MATCHED is UNVALUED (§7.0); §7.3 lists only equity lines and ONA, so a non-equity unmatched line
   belongs to neither sum.

## Reproduction / evidence

`tests/independent/test_I_compare_workers.py::test_I_CMP_13b_*` and `13c_*` record which reading the 03-nav reference
takes (result WARNING). The clean-room implements both readings (`tests/independent/cleanroom/nav.py`, `mpt_basis=`).
Example: one debt line, q = 1e6, P = 102, disclosed 10.0 Cr → disclosed basis 10.0 Cr, market basis 10.2 Cr.

## Proposed resolution

Fix one basis in §7.3 and §7.4 (QA suggests q × P at `in_Price_Date` for priced POSITION lines, disclosed value only for ONA roles), state that `nav` is `None` when any POSITION is unmarkable, and add a T-NAV case with a debt position.
