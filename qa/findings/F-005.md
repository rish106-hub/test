# F-005: Control_Status vocabulary and precedence are not fully defined

| Field | Value |
|---|---|
| Severity | minor |
| Owner | 00-main |
| Contract section | §6 outputs, §6.3, D-014 |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

The contract names FAIL (D-014) and UNVALUED (§6.3). The value for a normal row ("OK") appears only in
test_pricing_contract.py. Undefined cases:
1. Absolute mode with a blank price **and** an unvalued security: FAIL or UNVALUED?
2. `Original_Market_Price` blank (NO_PRICE, §7.5a): status and price outputs?
3. Invalid inputs outside the validation column's bounds (shock ≤ −1, bias ≤ −1, MoS ≥ 1, absolute ≤ 0): Excel data validation
   only, or Control_Status FAIL?
4. Fundamental mode selecting a case whose FV is blank while Base is present: is the security UNVALUED for the selected FV?

## Reproduction / evidence

`test_I_CMP_10b_resolve_controls_ambiguity_status_precedence` records the 03-nav choices (WARNING). The clean-room reading puts FAIL ahead of UNVALUED (`tests/independent/cleanroom/controls.py`).

## Proposed resolution

List the status values (OK / FAIL: <reason> / UNVALUED) with a precedence rule and add T-PRC cases for 1–4.
