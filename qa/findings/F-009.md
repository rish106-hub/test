# F-009: Coverage caption rounding and coverage/freshness edge cases

| Field | Value |
|---|---|
| Severity | minor |
| Owner | 00-main |
| Contract section | §7.5b, §7.5c |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

1. **Rounding.** At exact half-way values Python `f"{x:.1f}"` (half-even on the binary value) and Excel/LibreOffice
   `TEXT(x,"0.0%")` (half away from zero) disagree. Verified in LibreOffice 24.2: 0.8325 → Python "83.2%", LibreOffice "83.3%";
   0.0125 → "1.2%" vs "1.3%"; 0.0625 → "6.2%" vs "6.3%". W-03 would then flag a caption mismatch between a correct Excel
   caption and a Python reference that uses format().
2. Status when a fund has **no equity lines** (equity coverage undefined).
3. `Max_Financials_Age_Days` when some MODEL_VALUED lines are undated: are they excluded from the max, or does the max become blank?
   T-NAV-17 asserts only the stale weight.
4. `Unvalued_Value_INR_Cr`: disclosed value or q × P at `in_Price_Date`? T-NAV-10 (100 Cr) cannot tell them apart.

## Reproduction / evidence

Rounding: a LibreOffice 24.2 run of `TEXT(x,"0.0%")` vs Python format for x in {0.8325, 0.0125, 0.0625, 0.1015} (2026-10-25). The clean-room readings are marked QA-READING in `tests/independent/cleanroom/nav.py`.

## Proposed resolution

Fix the rounding to Excel's (half away from zero, e.g. `ROUND(x*100,1)`) in both the formula and the Python reference, and add a T-NAV case at 0.8325. Define 2–4 in §7.5.
