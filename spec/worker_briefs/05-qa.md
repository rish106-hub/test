# Brief 05-qa: Independent reviewer

**Launch:** `claude --worktree 05-qa --model opus --effort high "Read CLAUDE.md and spec/worker_briefs/05-qa.md, then execute the brief."`

## Mission

Independently establish whether the generated workbook is correct, and record **only what you actually executed**. You are the check on the math, the data provenance and the labelling. You report findings; you never fix another worker's code.

## You own

`tests/independent/**`, `tests/workbook/**` and `qa/**`. You produce `build/out/validation_results.csv` (schema `validation_results`), which 00-main renders on VALIDATION_CHECKS.

## Clean-room rule

Write `tests/independent/` from `spec/` and `src/common/` **only**. Do not open the bodies in `src/valuations/`, `src/fund_nav/`, `src/scenarios/`, `src/peers/` or `src/ingestion/`. You may import their functions to compare results, and you may read their signatures through `help()` or the stub docstrings. If the contract is ambiguous enough that two careful readers would implement it differently, that is a finding against the contract (route it to 00-main).

## Work

Start immediately against the test build. Re-run on every integration build.

1. **I layer** (`tests/independent/`): your own implementations of contract §3.1–3.6, §4, §6 and §7.2–7.6, plus property tests:
   * RI, DDM and P/B agree in steady state for random (r, ROE, payout) with g < r;
   * Method 1 equals Method 2 when weights equal q × P / NA;
   * sector contributions sum to the total;
   * Scenario NAV equals Official NAV at default controls;
   * a monotone FV change moves the NAV monotonically;
   * coverage lies in [0, 1].
   Run them against the workers' reference functions on synthetic **and** real canonical data.
2. **W layer** (`tests/workbook/`): implement W-01…W-16 from `spec/test_plan.md` §W. Use `build/recalc.py`; never trust cached values. For W-10 (spec manual tests 1–8), build the perturbation harness: copy the workbook, set input cells with openpyxl, recalculate, compare. First prove that an unperturbed round trip is value-identical.
3. **Data provenance audit** (`qa/provenance_audit.md`): sample at least 10% of `source_log` rows, stratified by entity and metric. Open the cited document and page, and confirm value, unit, period and basis. Also check every `source_manifest` SHA256 against `data/raw`. Report the sample, the method and every mismatch.
4. **Financial review** (`qa/financial_review.md`) against spec `<financial_checks>` and `<portfolio_checks>`: units, share counts and corporate actions, discounting periods and signs, g < r, method fit, diluted shares, holdings contamination, labels. Each item is PASS, WARNING or FAIL **with evidence**, or NOT RUN.
5. **Completion criteria** (`qa/completion_criteria.md`): every `<completion_criteria>` item from the v3 spec with its status and evidence. Nothing is marked met without an executed check.
6. **E layer**: run E-01…E-04 once the production build has real HDFC Bank data and holdings.
7. **Runner** `qa/run_validation.py`: runs the I, W and E suites, and writes `build/out/validation_results.csv` with `Executed`, `Result`, `Evidence` and `Tool` (pytest node id).
8. **Findings**: `qa/findings/F-<nnn>.md`, giving severity (blocker/major/minor), the owner, a reproduction, expected vs actual, and the contract section. 00-main routes each one.

## Rules

* A skipped, errored or unexecuted test is `NOT RUN`, never PASS.
* Do not loosen a tolerance to make something pass. Report the observed error instead.
* Historical/backtest checks (§H) are NOT RUN unless point-in-time data exists. Say why.

## Done when

- [ ] I and W suites run green on the latest integration test build, or every failure has a finding
- [ ] The provenance audit and financial review exist for the latest production build
- [ ] `validation_results.csv` is produced by `qa/run_validation.py`, not written by hand
