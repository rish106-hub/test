# F-012: QA cannot recompute the bank valuation from the workbook or the data: no reference-input interface

| Field | Value |
|---|---|
| Severity | major |
| Owner | 00-main (contract/module contracts); affects 02-valuation |
| Contract section | G1, W-03 (out_*), W-14, W-16, W-19, E-01; schema.VALUATION_OUTPUTS notes |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

Gate G1 requires "05-qa's clean-room implementation agrees with the 02 and 03 reference functions on that real data".
For 03 this is possible (holdings, controls and NAV are interface tables). For 02 it is not:
* nothing defines how canonical rows (raw_financials Metric_IDs, assumptions.csv rows) map to the arguments of
  `residual_income_value`, `equity_bridge`, `roll_forward_value` and `project_bank` for HDFC Bank. Driver years, BV_0 basis,
  interim periods and dividend ex-dates are 02's private layout;
* `schema.VALUATION_OUTPUTS` notes say the Python reference run writes `build/out/reference_valuation_outputs.csv`, but no
  module contract or brief obliges 02-valuation to write it;
* the sensitivity grids (W-14, TV-1/TV-5), the per-share BV displays (W-16, W-19) and the VAL_* inputs behind `out_*` (W-03)
  live on VAL_* sheets with no tbl_*/name interface, so QA cannot locate them generically.
W-03e therefore checks only that out_* equals tbl_ValuationOutputs, and W-14b is NOT RUN.

## Reproduction / evidence

`tests/workbook/test_W_values.py::test_W_14b_*` (NOT RUN, cites this finding), W-03e evidence, and E-01 evidence.

## Proposed resolution

Oblige 02-valuation to emit, per valued security, `build/out/reference_inputs/<SID>.json` (the exact arguments passed to each reference function, with Source_IDs) and `reference_valuation_outputs.csv`. Also expose private tables `tbl_Val_<SID>_Inputs`, `tbl_Val_<SID>_Bridge` and `tbl_Val_<SID>_Sensitivity` (r, g, value). QA then recomputes HDFC Bank clean-room from the same inputs (E-01).
