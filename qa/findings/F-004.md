# F-004: Reset_* columns and Controls_At_Default have no legal home; W-11 cannot pass as specified

| Field | Value |
|---|---|
| Severity | major |
| Owner | 00-main (schema, module contract, 03-nav brief) |
| Contract section | §6.3, W-11, schema.PRICE_CONTROLS, D-027, 03-nav brief item 2 |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

* The 03-nav brief (item 2) tells 03-nav to put `Reset_*` columns and a `Controls_At_Default` check in tbl_PriceControls,
  and §6.3 says "a `Reset` column computes the default for every input".
* `schema.PRICE_CONTROLS` has no `Reset_*` or `Controls_At_Default` column. `tools/check_module_contract.py`
  rejects a built table whose columns differ from the schema (`columns differ from schema`). If 03-nav follows its brief,
  it is REJECTED at the D-027 gate.
* §6.3 and START_HERE say VALIDATION_CHECKS (00-main's sheet) shows `Controls_At_Default`. No interface name or column
  carries that value from SCENARIO_ANALYSIS to VALIDATION_CHECKS.
* W-11 therefore has no defined cell to read. QA currently searches for a label `Controls_At_Default` next to a TRUE value.

## Reproduction / evidence

`tests/workbook/test_W_values.py::test_W_11_*` (evidence lists the cells found); grep of spec/ and build/ shows no schema or name for Controls_At_Default.

## Proposed resolution

Either add the `Reset_<input>` columns and `Controls_At_Default` to schema.PRICE_CONTROLS, or allow them as a private table `tbl_Nav_Reset` and define a name `out_Controls_At_Default` for VALIDATION_CHECKS. Then update W-11.
