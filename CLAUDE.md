# CLAUDE.md: Indian Equity Valuation and MF NAV Engine

This repository generates one formula-driven Excel workbook, `Indian_Equity_Valuation_and_MF_NAV_Model.xlsx`. It values Indian listed companies (starting with 6 banks and Max Financial) and estimates the modelled intrinsic value per unit of Parag Parikh Flexi Cap and HDFC Mid Cap (Direct Plan, Growth). The requirement is spec v3.0, `spec/source/Indian_Equity_Valuation_and_MF_NAV_Model_v3.xml`; the files in `spec/` turn it into a contract. Several Claude sessions work in parallel git worktrees. **This file and `spec/` are the shared contract between them.**

## Read before doing anything

1. Your brief: `spec/worker_briefs/<your-id>.md`.
2. `spec/financial_model_contract.md`: the only definitions of fair value, NAV methods, weights, coverage, scenario controls and units.
3. `spec/data_schema.md` (generated from `src/common/schema.py`), `spec/workbook_interface.md`, `spec/module_contracts.toml` (what your module must deliver) and `spec/decisions.md`.
4. `spec/test_plan.md`: what "done" is measured against.

## Engineering rules

* **Never edit or commit an `.xlsx`.** The workbook is generated by `build/generate_workbook.py` into `build/out/` (git-ignored). Git cannot merge binary workbooks (D-001).
* Touch the workbook only through `WorkbookContext` (`src/common/workbook.py`). Cross-module references go only through interface tables (`tbl_*`) and defined names (`in_*`, `out_*`) listed in `spec/workbook_interface.md` §2.
* Formulas may use only functions in `src/common/excel_contract.py::FUNCTION_WHITELIST`: INDEX/MATCH, not XLOOKUP, LET, dynamic arrays, INDIRECT or OFFSET. The QA harness recalculates in LibreOffice 24.2, which lacks the newer functions (D-002).
* Use `src/common/link_patterns.py` for cross-table links. `INDEX` of a blank cell returns **0**, which would value an unvalued holding at zero (WI-7, D-022).
* Every interface formula has a Python reference function in its module. The workbook result must equal it (D-020).
* Units: aggregates in INR crore, per-share values in INR, percentages as decimals, quantities as absolute counts. Conversions only via `src/common/units.py` constants (contract §0).
* Cell font colours: blue = input, black = same-sheet formula, green = cross-sheet link, grey = imported, purple = override/hypothetical (`src/common/styles.py`).

## Non-negotiables (from spec v3 `<non_negotiable_rules>`)

* **R001: never fabricate** financials, prices, holdings, estimates, ownership, ratios or citations. If a value cannot be retrieved, leave it blank, add it to `missing_data.csv` and explain the impact.
* R002: every reported input traces through `Source_ID` → `source_log` → `source_manifest`, with URL/file, period, unit and page.
* R004: no FCFF/WACC DCF as a bank's primary method. Use Residual Income, then DDM, justified P/B and peer-relative.
* R006 / R011: Official NAV, Modelled Intrinsic Value per Unit, Scenario Market NAV, Hypothetical Rebalanced Portfolio Value and Target Purchase Price are **five distinct outputs**, each with its fixed `OutputLabel` caption.
* R007 / R008: market-price and fair-value controls are independent, and neither ever overwrites an original price, a model value or imported data.
* R009: an unvalued holding stays visibly unvalued. It is never 0 and never hidden, and coverage is always disclosed.
* Data quality is three separate measures: holdings coverage, valuation coverage and freshness (contract §7.5). They are never blended into one score. The five model dates (contract §0.1) are never merged, and a reported figure is never relabelled as current.
* Synthetic fixtures (`SYNTHETIC TEST FIXTURE`, `SRC-SYNTH*`) are for tests only. A production build rejects them (D-013).
* A test is reported only if it ran. Anything else is `NOT RUN`, never PASS.

## Commands

```
pip install -r requirements.txt                           # xlsxwriter, openpyxl, pandas, pytest; LibreOffice for -m workbook
python -m pytest                                          # unimplemented contract tests show as SKIPPED (owner named)
python -m pytest --strict-impl                            # merge / QA gate
python -m pytest -m workbook                              # needs LibreOffice (soffice)
python build/generate_workbook.py --test-build            # synthetic, watermarked
python build/generate_workbook.py --test-build --only 03-nav   # your module + stubbed interfaces
python build/generate_workbook.py                         # production, from data/canonical
python build/recalc.py build/out/Indian_Equity_Valuation_and_MF_NAV_Model.xlsx   # real recalculated values
python tools/render_schema_doc.py --check                 # schema doc in sync
python tools/make_synthetic_fixtures.py --check           # fixtures in sync with tests/contract/cases.py
python tools/check_ownership.py <id> <base-ref>
python tools/check_module_contract.py <id> --manifest build/out/manifest.json --run-tests   # delivery gate (D-027)
```

## Workflow

1. Work in your worktree branch, which is based on the integration branch (currently `claude/financial-modeling-architecture-o2xiwz`).
2. Make your contract tests pass under `--strict-impl`. Add your own tests under your owned `tests/` folder. Fill in your `MODULE.md` (inputs, outputs, assumptions, limitations, tests).
3. Build your sheets in isolation with `--test-build --only <id>`, recalculate, and check the values.
4. Run `tools/check_module_contract.py` on your isolated build. Commit only owned paths, push, and tell 00-main. 00-main rejects a module that fails the check, merges in the order 01 → 02 → 04 → 03, runs the gates in `spec/worker_briefs/00-main.md`, then 05-qa validates the integrated build.
5. Wave 1 is HDFC Bank → its fund only. Nothing scales to more companies, holdings or charts until gate G1 passes (D-028).
6. Merge the integration branch into your branch whenever 00-main announces a contract change.
