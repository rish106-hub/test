# F-015: tests/test_common_module_contracts.py fails as soon as any worker fills in its MODULE.md

| Field | Value |
|---|---|
| Severity | major |
| Owner | 00-main (tests/test_common_module_contracts.py) |
| Contract section | D-027, spec/module_contracts.toml, CLAUDE.md workflow step 2 |
| Status | Open (reported 2026-10-25 by 05-qa) |

## Observation (expected vs actual)

`test_module_doc_templates_are_rejected_until_filled` iterates over **every real module** and asserts `check_doc(c)` is
non-empty: the real `MODULE.md` must still be the TODO template. D-027, each worker brief and
`tools/check_module_contract.py` require each worker to fill in its MODULE.md. The test therefore fails on every worker
branch that completes its delivery document, and on the integration branch after the first such merge. Its intent (the
TODO template must be rejected) is already covered by the `tmp_path` half of the same test, which could check a copy of the
template instead of the live files.

Expected: `python -m pytest` stays green when a worker fills in MODULE.md as required.
Actual: `FAILED tests/test_common_module_contracts.py::test_module_doc_templates_are_rejected_until_filled - AssertionError:
05-qa: the TODO template must not pass` once `qa/MODULE.md` is filled. `python tools/check_module_contract.py 05-qa` reports
`module contract OK for 05-qa`.

## Reproduction / evidence

On branch `wave1/05-qa`, run `python -m pytest tests/test_common_module_contracts.py -q`. The two requirements cannot both be
met. 05-qa keeps MODULE.md filled (the delivery gate) and leaves this one test failing; it does not edit 00-main's test.

## Proposed resolution

Run the template-rejection check on a fixed copy of the template (e.g. `tests/fixtures/MODULE_template.md`) instead of the live
module docs, or restrict it to modules whose doc still contains "TODO".
