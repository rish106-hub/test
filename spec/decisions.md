# Architecture Decisions

Each entry records a choice made, or an ambiguity in the v3 spec resolved, by the architecture session. Changing one requires a change request (`spec/change_requests/`) and a governance log row.

| ID | Decision | Why |
|---|---|---|
| D-001 | The workbook is generated by Python (XlsxWriter) from module-owned source files. No `.xlsx` is hand-edited or committed. | Git cannot merge binary workbooks, and five parallel sessions would overwrite each other. Generation makes every cell reproducible and reviewable as a code diff. |
| D-002 | Core formulas use only the whitelist in `excel_contract.py`: functions that evaluate identically in Excel 365 and LibreOffice 24.2. XLOOKUP and LET are banned. | The QA harness recalculates in LibreOffice to check Excel results against the Python reference. XLOOKUP and LET return `#NAME?` there (verified 2026-10-25), and INDEX/MATCH is equivalent. Independent verification is worth more than syntax. |
| D-003 | *Superseded by D-023 (v1.1).* Originally kept both of the spec's Target Purchase Price formulas as two outputs. | Two outputs with the same name would invite the reader to pick whichever looked better. |
| D-004 | Method 2 (quantity-based NAV) uses the ratio form `Official_NAV(plan) × NA_fair / NA_mkt`. The units form is secondary and used only when plan-level units are disclosed. | One scheme portfolio is shared by Direct and Regular, Growth and IDCW. Dividing scheme quantities by one plan's units would be wrong. The ratio form is exact, and it equals the spec's form with NAV-equivalent units. |
| D-005 | Valuation coverage is reported two ways: total (net-asset denominator, as the spec says) and equity. Cash, receivables and payables are `CARRYING_VALUE` and count as covered. It is one of the three data-quality measures in D-026. | Under the spec's denominator, a fund holding cash could never reach 100% coverage, which would make the warning meaningless. |
| D-006 | Global, sector and per-security price shocks compound multiplicatively and apply only in `Market Price Shock` mode. Precedence and the apply-once rule are in D-024. | The spec's manual test 8 needs sector shocks, and the spec does not say how they combine. Multiplying is order-independent and keeps `Original × (1 + shock)` when the other shocks are 0. |
| D-007 | Banks and insurers are valued at an anchor date (the latest reported fiscal-year balance sheet), then rolled forward to the valuation date, net of dividends that went ex in between. Made explicit by D-025. | Indian fiscal years end on 31 March, while the valuation date is arbitrary. This avoids ad-hoc stub-period discounting. |
| D-008 | Bear and Bull values come from re-running the model on full alternative driver sets. They are never Base × (1 ± k). | Spec `<general_principle>` and `<uncertainty>`. |
| D-009 | Method blend weights default to 100% on the primary method. The other methods are shown as cross-checks, and weights are recorded user assumptions. | Inventing blend weights would be an unexplained judgement. |
| D-010 | `Entity_ID` (issuer) is separate from `Security_ID` (instrument). ISIN is the match key and Security_ID the join key. Names are never keys. | Spec `<unique_identifier_rule>`. ISINs can change after corporate actions; Security_IDs never do. |
| D-011 | Canonical units: aggregates in INR crore, per share in INR, percentages as decimals, quantities as absolute counts. Lakh values are converted to crore at import, keeping the raw value. | AMC disclosures use lakh, filings use crore and prices are in rupees. One convention per column suffix prevents ×100 and ×1e7 errors. |
| D-012 | Five sheets are added to the spec list: DATA_FEASIBILITY, VALUATION_ASSUMPTIONS, VALUATION_OUTPUTS, FUND_PERFORMANCE and VALIDATION_CHECKS. | The spec requires these deliverables (feasibility report, assumptions, the valuation-to-NAV interface, the performance metrics, executed-test report) without giving them a sheet. |
| D-013 | Synthetic fixtures carry `SYNTHETIC TEST FIXTURE` status and `SRC-SYNTH*` source IDs. A production build rejects them, and a test build watermarks every sheet. | R001: synthetic numbers must never be able to pass as data. |
| D-014 | `Absolute Scenario Market Price` mode with a blank price returns `#N/A` and `Control_Status = FAIL`. It never falls back silently. | A silent fallback would make a scenario look applied when it was not. |
| D-015 | An unvalued equity holding is carried at market price (adjustment 0) in Methods 1–3. It is flagged, counted in unvalued weight and named in the coverage caption. | R009 and spec `<coverage_rules>`: it is neither zero nor hidden. |
| D-016 | Canonical data is CSV, append-only for observations, with revisions linked by `Supersedes_Observation_ID`. Raw source files go under `data/raw/` with a SHA256 in `source_manifest.csv`. When licensing forbids committing a file, only its URL and hash are kept. | Spec `<pipeline_rules>`. It also keeps data diffable and mergeable. |
| D-017 | Only 04-charts creates charts, rendering into zones that sheet owners reserve. | One consistent chart style and metadata standard, with no sheet-layout collisions between workers. |
| D-018 | Fiscal labels: `FY2026` = Apr-2025 to Mar-2026, and `Q1FY2027` ends Jun-2026. | Indian reporting convention. |
| D-019 | The headline fair NAV is Method 1. Method 2 is shown alongside, and `Method_Drift_INR = M1 − M2` measures weight drift since the portfolio date. | Method 1 is the spec's first method and needs only disclosed weights. The drift diagnostic tells the user when the static-portfolio assumption is weak. |
| D-020 | Excel and Python must agree. Every interface formula has a Python reference function. QA recalculates the workbook and compares named outputs to the reference outputs for identical inputs. | "Spend the extra effort on validation." Formula checks alone cannot catch a wrong but internally consistent formula. |
| D-021 | Table formulas are stored with fully qualified this-row references (`tbl_X[[#This Row],[Col]]`). `WorkbookContext` rewrites `[@Col]` automatically. | XlsxWriter's short form evaluates to `#N/A` in LibreOffice 24.2 (verified 2026-10-25), which would make QA recalculation impossible. Excel reads both forms. |
| D-022 | Cross-table links that may hit a blank cell use `link_patterns.blank_safe`. | `INDEX` of an empty cell returns 0 in both Excel and LibreOffice (verified). Without this guard an unvalued holding would silently get a fair value of 0 and a −100% adjustment (R009). |
| D-023 | **One Target Purchase Price**: `Selected_Scenario_Fair_Value × (1 − Required_Margin_of_Safety_Pct)`. `Model_FV_Base`, `Fair_Value_After_Bias` and `Selected_Scenario_Fair_Value` stay separate columns. Supersedes D-003. | Pre-launch review. The spec's two formulas agree at default controls (Selected = Base), so the selected form contains the base form. One canonical output removes the choice between two "targets". A market-price shock can never move it. |
| D-024 | Shocks are applied **once, from the original price**: `P_0 × (1 + s_global)(1 + s_sector)(1 + s_security)`, read only in `tbl_PriceControls[Effective_Shock_Pct]`. The mode alone selects the price, and Absolute mode overrides every percentage shock. Inputs that the selected mode ignores are named in `Control_Warning`. | Pre-launch review. It stops a shock being applied twice downstream (W-17 checks), and stops a user believing an ignored input is in effect. |
| D-025 | **The five model dates stay separate** (contract §0.1). The reported balance sheet at A is captioned as historical. An explicit **equity bridge** A → V (reported interim EPS, forecast stub EPS, dividends) gives the estimated BV at V. An interim-versus-forecast check flags out-of-date drivers, and financials freshness is tested against LODR deadlines. The value roll-forward of D-007 is kept. | Pre-launch review: an old balance sheet must not read as fresh, and changes after A must be forecast explicitly. The value roll-forward is already the expected value at V under the model's own forecasts, so it is kept. What was missing was showing the earnings and equity behind it, and noticing when reported interims contradict them. Re-anchoring on an interim balance sheet would need stub-period RI; that is left to a change request. |
| D-026 | **Three separate data-quality measures** per plan: (1) holdings coverage (imported value / reported net assets, and positions matched and priced), (2) valuation coverage (D-005), (3) data freshness (holdings, NAV and valued-financials age). Each has its own status. There is no composite score. A position that is not MATCHED is never MODEL_VALUED. | Pre-launch review. An imported holding can lack a valuation, and a valued holding can rest on stale financials. One blended number would hide which problem exists. |
| D-027 | **Module delivery contract** (`spec/module_contracts.toml`, `tools/check_module_contract.py`). Each worker delivers fixed consumed and produced interfaces, reference functions, contract tests and a filled-in `MODULE.md` (inputs, outputs, assumptions, limitations, tests). 00-main rejects any module that fails the check. | Pre-launch review. Ownership alone stops edits to other people's files. It does not stop a module quietly producing an extra table, dropping a column, or reading an interface it was not given. |
| D-028 | **Phased launch with a vertical-slice gate.** Wave 1 builds HDFC Bank to one actual holding to that fund's NAV (E-01…E-04), with 05-qa recomputing it clean-room. Scaling to all seven companies, every material holding and the charts waits for gate G1. | Pre-launch review: prove the financial calculations before multiplying models, charts and workers. |
| D-029 | **Contract v1.2: CR-03-nav-001 and CR-03-nav-002.** (1) The Bear/Bull/Selected holdings links and the line-value formulas join `link_patterns.py` (`H_ADJ`, `H_SELECTED_PRICE`, `H_SCENARIO_FV`, `H_FINANCIALS_AS_OF`, `H_MV_FAIR_BASE`, `H_MV_SCENARIO`). `H_MV_MKT` is fixed: in v1.1 a blank quantity gave a silent 0 (breaks R009), a NO_PRICE line gave `#VALUE!` (breaks W-02), and a MARKET_PASS_THROUGH position was marked at q × P instead of its disclosed value (§7.3). (2) `out_Controls_At_Default` (03-nav) is the interface for the reset check. (3) W-17 now reads: a shock is *applied* only in `Effective_Shock_Pct`; `Control_Warning` and the reset check may compare the raw inputs with their defaults. (4) The CR's proposal to test the *net* shock in §6.2 is **rejected**: an input the user set and the mode ignores must be disclosed even when shocks cancel exactly (T-PRC-13, hand-derived 0.8 × 1.25 = 1). Test: `tests/test_common_link_patterns.py` (LibreOffice) and T-PRC-13. | 03-nav, 05-qa (W-17 scan scope) |
| D-030 | **The full test build stubs every unbuilt module's interfaces**, not only in `--only` mode. Modules can then merge in any order, and Wave 1 can run without 04-charts, even though 02-valuation reads `tbl_PeerSummary`. The stub tables are labelled `STUB of …` with owner `STUB` in `manifest.json`, and the build report lists them. A production build never stubs, so a missing interface still fails at `close()`. Test: `test_test_build_and_isolated_builds_succeed` checks that only the interfaces of modules that did not build are stubbed. | 00-main |
